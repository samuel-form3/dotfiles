# Neovim 0.12 Single File Config Design

## Goal

Replace the current multi-file `lazy.nvim` Neovim config with a compact Neovim 0.12 config in `.config/nvim/init.lua`.

The config should favor built-in Neovim features, use the new `vim.pack` plugin manager, use `vim.lsp.config()` / `vim.lsp.enable()` for LSP, and keep only plugins that provide clear daily value.

## Plugin Scope

Keep:

- `saghen/blink.cmp` for completion.
- `folke/snacks.nvim` as the main picker, explorer, git, terminal, and utility package.
- `echasnovski/mini.nvim` for small editing conveniences and statusline.
- `stevearc/conform.nvim` for formatter-on-save.
- `nvim-treesitter/nvim-treesitter` for syntax highlighting and indentation.
- `folke/tokyonight.nvim` for the current colorscheme.
- `tpope/vim-sleuth` for indentation detection.

Remove:

- `folke/lazy.nvim`
- `folke/noice.nvim`
- `lewis6991/gitsigns.nvim`
- `sindrets/diffview.nvim`
- `j-hui/fidget.nvim`
- `ray-x/go.nvim`
- `ray-x/guihua.lua`
- `MagicDuck/grug-far.nvim`
- `andyg/leap.nvim`
- `towolf/vim-helm`
- `rafamadriz/friendly-snippets`

## File Layout

Use a single source file:

- `.config/nvim/init.lua`

Remove old Lua modules under:

- `.config/nvim/lua/config`
- `.config/nvim/lua/plugins`

Keep `.config/nvim/.stylua.toml`.

Remove `lazy-lock.json`. Use `vim.pack`'s lockfile instead when generated by Neovim.

## Config Sections

Organize `.config/nvim/init.lua` into compact sections:

1. Basics
2. Options
3. Keymaps
4. Autocmds
5. Plugins
6. Theme
7. Mini
8. Snacks
9. Completion
10. Treesitter
11. Formatting
12. LSP

## LSP

Use native Neovim 0.12 LSP config APIs only:

- `vim.lsp.config('gopls', ...)`
- `vim.lsp.config('terraformls', ...)`
- `vim.lsp.config('lua_ls', ...)`
- `vim.lsp.enable({ 'gopls', 'terraformls', 'lua_ls' })`

Do not add Mason. Language servers are expected to be installed by system tooling and available on `PATH`.

Keep compact LSP keymaps on `LspAttach`:

- Rename
- Code action
- Hover
- Definition, declaration, references, implementation, and type definition
- Document and workspace symbols through Snacks
- Diagnostics via built-in Neovim APIs

Keep diagnostic configuration simple: virtual text, underline, sorted severity, and rounded floats.

## Completion

Use `blink.cmp` for completion. Do not add a snippets plugin in this migration.

Keep the config minimal:

- LSP, path, buffer sources.
- Signature help enabled.
- Default keymap preset.

## Formatting

Use `conform.nvim` on save with the existing formatter intent:

- Lua: `stylua`
- Go: `goimports`, `gofumpt`
- Terraform: `terraform_fmt`
- Proto: `buf`

Keep a manual format keymap.

## Go Workflow

Remove `go.nvim`. Replace Go test plugin commands with simple keymaps that run `go test` through Neovim commands:

- Current package.
- Current package.

Do not recreate every `go.nvim` feature.

## Search And Replace

Use `snacks.nvim` for file search, grep, buffers, explorer, diagnostics, and LSP pickers.

Remove `grug-far.nvim`. Use native substitute commands and quickfix for occasional project-wide replacement.

## Verification

Validate with:

- `nvim --headless +q`
- `nvim --headless '+checkhealth vim.pack' +q`
- `stylua --check .config/nvim/init.lua`, if `stylua` is installed.

The implementation is complete when Neovim starts without config errors and the file contains only the agreed plugin set.
